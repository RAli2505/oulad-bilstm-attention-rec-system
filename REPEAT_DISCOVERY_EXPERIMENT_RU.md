# Эксперимент: повторное обращение и открытие новых ресурсов

Подготовлен 4 ноября 2026 года. Полный запуск при подготовке не выполнялся.

## Что сравнивается

- Фиксированные доли повторных ресурсов: 0%, 25%, 50%, 75%, 100%.
- Адаптивная доля из того же набора; выбор для каждого обучающегося по наблюдаемой истории.
- Лучший фиксированный вариант, выбранный исключительно на selection.
- Гибрид без ограничения доли и без MMR; исходный гибрид с MMR как дополнительный ориентир.
- LastVisited, MostFrequent и Popularity. Все методы используют одинаковый полный доступный каталог и допускают повторные рекомендации.

Окна: дни 7, 14, 28, 56. Будущая релевантность: сохранённые обращения в следующие семь дней. K: 5, 10, 20. Пять seed: 42, 13, 7, 23, 101; это пять инициализаций исходной модели при одном разделении обучающихся.

## Адаптивная политика

Небольшая модель Ridge оценивает ожидаемый NDCG@10 для каждой фиксированной доли. Обучение выполняется на fit. Регуляризация выбирается из 0.1, 1, 10, 100 по NDCG@10 на selection. Повторного обучения на fit+selection после выбора нет. Оценочная held-часть не участвует в выборе.

Признаки: число посещённых доступных ресурсов, сумма ресурс-дней, концентрация обращений, уверенность поведенческого профиля, разброс предпочтений, доля посещённых ресурсов с обращением в последние семь дней и день курса. Все признаки используют только историю до cutoff. Политика не является прогнозом учебного риска.

Внутри групп используются одинаковые замороженные гибридные оценки и последовательный селектор. MMR для сравнения долей отключён. После выбора состава списка позиции сортируются по замороженной гибридной оценке. Доля округляется отдельно для каждого K: половина округляется вверх. При недостатке кандидатов оставшиеся позиции заполняются из другой группы. Поэтому 0% и 100% — целевые квоты с дозаполнением, а не строгий запрет другой группы. Фактические доли сохраняются.

LastVisited упорядочивает ресурсы по последнему положительному обращению, MostFrequent — по сумме прошлых кликов. Равенства разрешаются популярностью, затем ID ресурса. Popularity использует только прошлые клики fit-обучающихся того же курса и презентации. У никогда не посещённых ресурсов персональные счётчики равны нулю; для LastVisited дата равна отрицательному служебному значению.

## Граница test

Для точных LastVisited и MostFrequent читается общий журнал studentVle.csv, содержащий несколько лет. Перед числовым разбором строки отбираются по 2013B/2013J, дате строго до cutoff и положительным кликам. Строки 2014 не разбираются в таблицу и не участвуют ни в признаках, ни в оценке. Итоговый studentInfo.csv не читается. Все сохранённые исходные модели и результаты остаются неизменными.

Held уже просматривался ранее, поэтому результаты остаются exploratory validation, а не финальным независимым подтверждением. Параметры не подбирать по held. Рост метрик будущих обращений не доказывает рост усвоения знаний.

## Метрики и выводы

Главное заранее определённое сравнение: adaptive против selection-best-fixed, NDCG@10. Дополнительно сохраняются Precision, Recall, MAP, MRR, заполнение списка, фактические доли, покрытие каталога и новых ресурсов.

Для повторных и новых положительных ресурсов отдельно вычисляются Recall и NDCG с сохранением исходных позиций в списке. При отсутствии соответствующих будущих положительных ресурсов метрика отсутствует, а не приравнивается к нулю. Количество поддерживаемых запросов приводится явно. Покрытие — доля уникальных рекомендованных (курс, презентация, ресурс) в объединении доступных held-каталогов; покрытие новых — аналогично для ресурсов, новых хотя бы для одного held-запроса. Такая величина не является показателем полезности обучения.

Парные интервалы: 1000 bootstrap-повторов с группировкой по обучающемуся. Дополнительные сравнения имеют нескорректированные интервалы и считаются разведочными. Между seed сохраняются среднее и SD, а не независимые выборочные интервалы.

Оптимизация выполняется по общему NDCG@10. Автоматическое улучшение открытия новых ресурсов не гарантируется: возможен выбор преимущественно повторных рекомендаций. Если адаптация не превосходит фиксированные правила или не даёт полезного компромисса, положительный вывод о новизне не делать.

## Ресурсы, журнал и восстановление

Замороженные risk/SVD/SASRec/fusion не переобучаются. Новое обучение — только маленькая CPU-модель выбора квоты. Данные обрабатываются массивами, инференс fusion выполняется пакетами, число потоков ограничено шестью. GPU для этого эксперимента не требуется.

Выход: `runs/repeat_discovery_balance_v1`. Сохраняются UTF-8 журналы с местным HH:MM UTC+05:00, контрольные суммы входов/кода, конфигурация, progress.json, RSS и CPU/wall time по заданиям. Длительные стадии имеют heartbeat каждые 20 секунд; для счётных стадий выводятся скорость и измеренная ETA текущей стадии. Общее время до реального замера не обещается.

Восстановление: история — по дню; подготовка — каждые 256 запросов; оценка и bootstrap — по дню/seed. После сбоя могут повториться инференс исходной fusion и незавершённый блок подготовки, либо незавершённая оценка/обучение маленькой политики. Повторная проверка входов обязательна. При изменении входов, кода, конфигурации или окружения продолжение отвергается. Параллельные писатели в одну папку запрещены. Существующую папку для нового запуска не перезаписывать; использовать Resume или другое --output.

Главные результаты: summary.csv, across_seed_summary.csv, paired_differences.csv. В каждой папке day/seed: selection.json, quota_policy.joblib и query_metrics.parquet с конкретными рекомендациями для аудита.
