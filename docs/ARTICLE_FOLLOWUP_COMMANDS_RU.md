# Дополнительные эксперименты статьи

Все три команды запускаются пользователем. Исходные risk/full_agent результаты
используются для чтения; новый результат помещается в отдельный каталог runs.
Каждый запуск пишет время HH:MM, консольный/файловый лог и контрольные точки.
Для продолжения повторить исходную команду с добавленным `--resume <новый каталог результата>`.
Параметры, данные, исходники и версии при resume должны совпадать.

## Практическая оценка риска и группы

`run_risk_practical_reports.py --risk-run <risk_run> --windows 7 14 21 28 56 112 --seeds 42 13 7 23 101 --capacities 0.1 0.2 0.3 --threads 6 --bootstrap 1000`

Без обучения. Вероятности пяти seed усредняются. Численный порог фиксируется на
selection, применение к held может дать другую долю выбранных. Отдельный режим
fixed_capacity_ranking выбирает ровно ceil(capacity*N) наиболее рискованных
записей. Единица бюджета — запись студент–курс, не дедуплицированный человек.
Групповые отчёты: курс, поток, пол, возраст, disability, IMD, образование.
Малые группы помечаются. Порог не выбирается по лучшим held-метрикам.
Файлы: capacity_summary.csv, subgroup_summary.csv. Контрольная точка — отчёт окна.

## Абляции и обновление предпочтений

`run_recommendation_controls.py --agent-run <full_agent_run> --windows 7 14 21 28 --seed 42 --threads 6 --bootstrap 1000`

Заново обучается только согласование сигналов; SVD/SASRec/риск заморожены.
Полная контрольная версия full_refit также обучается с тем же бюджетом C.
Это контролируемые версии с выбором C по selection NDCG и Recall, а не точное
повторение production fallback gate. Held не выбирает параметры.

Варианты: полная версия, без явных preference/confidence, risk_calendar, CF,
content, SASRec, MMR; профиль, замороженный на дне7. При удалении CF/content
удаляется также зависимый сигнал выбранной стратегии. Это удаление сигналов
с повторным обучением согласования, не повторное обучение всего encoder.
Профиль day7 сравнивается с обновляемым на day14/21/28; другие компоненты в
обоих случаях используют одну текущую историю. Для отсутствующих day7
студентов/типов сигнал замороженного профиля нейтрализуется нулём.
Следовательно, это проверка обновления явных предпочтений, не всей адаптации.
Релевантность и доступные кандидаты, включая повторы, одинаковы.
Файлы: summary.csv, paired_differences.csv; интервалы отдельных сравнений
не скорректированы за множественность и интерпретируются как exploratory.
Контрольная точка — завершённый вариант на одном окне.

## Ранее не встречавшийся курс

`run_course_transfer.py --risk-run <risk_run> --windows 28 56 112 --seeds 42 --device cuda --threads 6`

Это отдельное обучение. Каждый курс по очереди полностью исключается из
fit/selection/calibration. Его студенты исключаются также из обучения на других
курсах. Внутренний подбор и калибровка происходят только на оставшихся курсах.
Обучаются BiLSTM Attention, LSTM, LightGBM и их ансамбль. Используются только
потоки 2013; тест2014 не участвует. Словарь известных метаданных курса не
равнозначен обучению по его меткам. Преобразования fit-only, неизвестные категории
обрабатываются имеющимся encoder.

По умолчанию все курсы 2013; `--courses BBB CCC` ограничивает заранее выбранный
список. Один seed — начальная проверка переноса; для оценки устойчивости следует
запланировать пять seed до запуска. При изменении списка seed нужен отдельный
запуск, потому что здесь конфигурация resume строгая.
Файлы validation_2013_* в каждом held_<курс>/day_* — это результаты исключённого
курса; старые подписи о номинальном 70/30 здесь не применяются. Правильное
разделение записано в course_transfer_audit.json. Контрольная точка — завершённый
курс/окно, а внутренние готовые задания повторно используются штатным pipeline.
