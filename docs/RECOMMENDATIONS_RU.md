# Адаптивный рекомендательный модуль OULAD

Модуль находится в `recommendations/` и использует готовую вероятность
неуспешного завершения курса от LSTM + BiLSTM Attention + LightGBM.
Он не обучает ансамбль, не меняет его признаки, веса или калибровку.
Рекомендационные score — относительные оценки для ранжирования, а не
новые вероятности неуспеха и не оценки причинного эффекта материала.

## Что перенесено из xes-mars

Из `agents/recommendation_agent.py` использованы идеи объединения нескольких
видов доказательств, объяснимого ранжирования и разнообразия MMR.
Из `recommendation_signals.py` — разделение исходных прогнозов и производных
рекомендационных сигналов. Исходные файлы xes-mars не изменяются.

OULAD не содержит тех же тематических вероятностей пробелов, ответов на
вопросы и оценок IRT. Поэтому исходный код нельзя копировать буквально:
общий риск курса не преобразуется в вероятность незнания каждой темы.
FAISS/Sentence-BERT, граф знаний, CF по правильности ответов и Thompson
Sampling не переносятся без соответствующих данных и обратной связи.

## Модель предпочтений

Профиль строится отдельно для `(id_student, code_module, code_presentation)`
по исходным взаимодействиям с сохранением `id_site`.
Используются только события `date < as_of_day`; метки исхода, оценки
заданий и будущие действия не участвуют.

Для ресурса за один день сначала суммируются клики, затем берётся
`log(1 + min(clicks, 20))`. Повторные клики имеют ограниченный вклад.
Давность учитывается множителем `2 ** (-age / 14)`; период полураспада
настраивается. Для каждого типа материала вклад нормируется на число
доступных или уже наблюдавшихся ресурсов этого типа, затем добавляется нейтральный prior
с общей силой 3. Полученный вектор суммируется до 1.

При короткой истории сглаживание удерживает предпочтения около нейтральных.
Уверенность равна `effective_resource_days / (effective_resource_days + 3)`.
Профиль содержит также последние посещения, энтропию и разницу между долями
типов за последние семь дней и более старой историей. Это описательная
смена интересов, а не статистически подтверждённый drift.

Поправка на число ресурсов приближённая: OULAD не содержит логов показов,
поэтому обязательность заданий и реальную возможность выбора отделить
полностью нельзя. Кликовая активность не доказывает осознанный интерес.
Истечение доступности удаляет материал только из кандидатов: прошлые
посещения и соответствующие предпочтения сохраняются.

## Рекомендации и адаптация

Рекомендации выбираются из каталога текущего курса. Будущие плановые
материалы и ресурсы с ещё не наступившей явной датой доступности исключаются.
`available_from_day`/`available_until_day`, если заданы, описывают реальные
границы доступности. `week_from`/`week_to` OULAD описывают учебный план:
начальная неделя используется как консервативный фильтр, последняя —
для календарной релевантности, а не как дата удаления материала.
Неизвестные недели допустимы и явно отмечаются в результате.

Ранжирование сочетает предпочтения, календарную релевантность и давность
посещения. При риске `r` веса равны `0.5`, `0.2 + 0.2*r`, `0.3 - 0.2*r`.
Это начальная эвристика, не обученные оптимальные веса. Риск усиливает
календарный приоритет, но не сообщает, какой ресурс снизит риск.
Разнообразие обеспечивается штрафом 0.15 за повтор уже выбранного типа.
По умолчанию исключаются ресурсы, посещённые за последние семь дней;
режим `allow_review` разрешает повторение.

После получения новых событий вызовите `agent.update_history(full_history)`
и повторите `recommend` с новым днём и соответствующим прогнозом.
Передаётся **полная обновлённая история**, а не приращение: повторная
передача одного снимка не удваивает события. Пересчёт происходит и при
изменении календаря, и при старении истории. Ансамбль при этом не обучается.

## Использование в Python

```python
import pandas as pd
from recommendations.recommendation_agent import RecommendationAgent
from recommendations.cli import read_forecast

key = (12345, 'AAA', '2013J')  # замените на существующую запись
day = 112
predictions = 'runs/<run>/day_112/validation_2013_predictions.csv'
probability = read_forecast(predictions, key, day, prediction_day=day)
agent = RecommendationAgent(resources, interactions)
snapshot = agent.recommend(key, day, probability, n=5)
agent.update_history(updated_full_interactions)
updated_snapshot = agent.recommend(key, next_day, next_day_probability, n=5)
```

`resources` имеет поля `id_site`, `code_module`, `code_presentation`,
`activity_type` и необязательные поля расписания. `interactions` — исходные
поля `studentVle.csv`: ключ зачисления, `id_site`, `date`, `sum_click`.
В отличие от существующего загрузчика для прогнозирования здесь нельзя
агрегировать историю только до `activity_type` с потерей `id_site`.

## Запуск с готовыми прогнозами

Из корня репозитория, подставив реального студента и курс:

```powershell
rtk proxy py -3.12 -X utf8 -m recommendations.cli --data-dir data/oulad/raw --predictions runs/risk_20261031T162709361455Z/day_112/validation_2013_predictions.csv --prediction-day 112 --student 12345 --module AAA --presentation 2013J --day 112 --n 5 --output test-artifacts/recommendation_example_112.json
```

Входные CSV читаются без записи. Из прогнозов выбирается ровно одна строка
по полному ключу, по умолчанию колонка
`ensemble_lstm_attention_lgbm_weighted_probability`. День прогноза должен
совпадать с днём рекомендации; имя каталога `day_N` дополнительно проверяется.
CLI читает только ключи и колонку вероятности, без исходов обучения.
История читается порциями, чтобы не держать весь studentVle в памяти.
JSON содержит исходную вероятность, SHA-256 источника прогнозов, профиль,
составляющие score, объяснения и ограничения. Существующий JSON не заменяется.

## Что подтверждено и что ещё исследовать

Проверки контролируют временные границы, идентичность зачисления, адаптацию,
насыщение кликов, холодный старт, доступность ресурсов и сохранение прогноза.
Код прогнозирующих моделей и исследовательские артефакты не изменяются.
Это сохраняет прежний способ получения прогнозов; новая оценка AUC
не выполняется и новое качество рекомендаций не заявляется.

Для диссертации нужен отдельный временной эксперимент NDCG@K/Recall@K:
история до t, рекомендации в t, фактические взаимодействия после t.
Контроли: календарь, популярность только по train, статические предпочтения,
адаптивные предпочтения, адаптивные предпочтения с риском и без него.
Подбор параметров — на внутренних данных; test 2014 остаётся закрытым.
Качество совпадения с будущими просмотрами не доказывает улучшение обучения.
