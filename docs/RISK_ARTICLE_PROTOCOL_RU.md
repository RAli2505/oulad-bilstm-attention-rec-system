# Протокол исследования основной модели BCE + Cox

## Запуск

Из корня репозитория:

```powershell
rtk proxy py -3.12 -u run_risk_article.py
```

Это основной pipeline для новой статьи. `run_article.py` относится к отдельному воспроизведению модели Omarbekova et al.; его результаты нельзя смешивать с этим исследованием.

По умолчанию: окна 28/56/112 дней, основное 56; 5 фолдов; seed 42/13/7; 14 моделей. Всего 630 обучений, каждое с собственным каталогом. Для нейросетей максимум 100 эпох, patience 20, min_delta 0.0001, batch 256, Adam lr 0.001. Гиперпараметры заранее фиксированы; это сравнение выбранных конфигураций, а не исчерпывающий поиск лучшей конфигурации каждого алгоритма.

Первичная гипотеза: совместное BCE + Cox улучшает ROC-AUC относительно той же сети без Cox на внешнем тесте при окне 56 дней. Веса Cox = 1. Остальные сравнения и окна — дополнительные, исследовательские. Изменение первичной гипотезы после просмотра теста требует нового независимого подтверждения.

## Задача и выборка

- Положительный класс: `Fail` или `Withdrawn`; отрицательный: `Pass` или `Distinction`.
- Прогноз в начале дня D; активность и сдачи с датой строго меньше D. Все варианты используют один источник данных и одну выборку данного окна.
- Включаются записи без VLE-активности. Не используется историческая фильтрация «не менее 10 активных дней».
- Исключаются ушедшие к дню D, ещё не зарегистрированные, завершившиеся курсы, Withdrawn с неизвестным временем ухода и неизвестные исходы. Все исключения считаются в отчёте; счётчики причин могут пересекаться.
- Cox-событие — именно уход (`Withdrawn`), а не составная метка Fail+Withdrawn. Время считается от D до ухода; не ушедшие цензурируются концом курса. Это дополнительная задача времени до ухода, связанная с основной классификацией, но не тождественная ей.
- Development: 2013B/J. Test: 2014B/J; все ученики, встречающиеся в development, удаляются из внешнего теста. Между внешними CV-фолдами и внутри train/validation также нет пересечения `id_student`.
- Состав выборки меняется между окнами: результаты каждого окна условны на продолжение обучения в момент D. Нельзя объяснять разницу AUC между окнами только добавленной историей.

## Признаки и доступность

Динамика: ежедневные клики по типам активности, только дни [0,D). Статика: демография, регистрационные признаки, число и наличие ранних сдач, факт переноса оценки. Числовые пропуски, категории, масштабы, активные каналы и статистики нормализации определяются только по внутренней fit-части.

В OULAD отсутствует реальное время публикации оценок. Поэтому основной анализ **исключает числовые оценки**, сохраняя архитектуру и наблюдаемые признаки сдачи. Пустые столбцы оценки остаются константами после imputation и не несут информации об исходе. Это сознательное отличие от исторического эксперимента AUC 0.87497.

Дополнительный анализ чувствительности можно отдельно запустить с `--score-policy proxy --score-lag 7`. Тогда оценка считается доступной после max(дата сдачи, дедлайн)+7 дней. Это допущение, а не подтверждённый timestamp; этот запуск не является основной оценкой без риска утечки оценок.

Динамические входы: log1p и train-only стандартизация по каналу. Классические методы получают ту же статику и агрегаты каждого канала: total/mean/std/max, последние/предыдущие 7 дней и разницу. Это сравнение способов представления одной наблюдаемой информации, а не одинаковых векторов входа.

## Модели

| Имя в результатах | Конфигурация |
|---|---|
| proposed | Историческая BiLSTM 2×128 + additive attention + статическая MLP 128→64 + fusion 64; BCE + Cox |
| lr | Logistic Regression, C=1, max_iter=2000 |
| rf | 300 деревьев, min_samples_leaf=2 |
| svm | RBF SVC, C=1, gamma=scale; без внутренней Platt CV |
| xgboost | 300 деревьев, depth=6, lr=.05, CPU histogram |
| lightgbm | 300 деревьев, 31 leaf, lr=.05, deterministic CPU |
| mlp | sklearn MLP 128→64, максимум 200 итераций, без внутреннего случайного validation split |
| lstm / bilstm | 2×128, конечные состояния + та же статическая MLP; BCE |
| transformer | 2 слоя, d_model=128, 4 heads, FFN=256, sinusoidal position, mean pooling + статика; BCE |
| no_attention | Основная модель с mean pooling вместо attention; BCE + Cox |
| no_static | Основная модель без статической ветви; BCE + Cox |
| no_cox | Та же архитектура и та же инициализация, что proposed; только BCE |
| paper_hybrid | Адаптация Omarbekova et al. 2026 (DOI 10.3389/frai.2026.1811886): недельные суммарные клики, BiLSTM 2×64, attention, статическая MLP, двухклассовый выход |

Модель статьи обучается заново на общей составной метке и общем cutoff. Это адаптированный baseline, а не буквальная репликация её выборки, метки или опубликованного AUC. Число параметров и полный repr сети сохраняются в training.json.

Cox использует корректный Breslow denominator для связанных времён, но риск-сеты ограничены minibatch. Это стохастическая minibatch-аппроксимация Cox, не полный risk-set likelihood. Размер батча сохраняется для воспроизводимости. Исходная историческая реализация не обрабатывала ties таким способом; новый результат не обязан повторить 0.87497.

## Обучение, калибровка и оценка

Каждый внешний train-фолд дополнительно делится на fit/validation по ученикам. Предобработка обучается только на fit. Для нейросетей единый критерий выбора эпохи — **raw validation BCE**, включая proposed; Cox помогает обучению, но не меняет критерий отбора эпохи. Test и внешний held-фолд не используются ни для выбора эпохи, ни для калибровки.

У каждого метода есть одна и та же Platt-калибровка на внутренней validation (StandardScaler score + LogisticRegression C=1). Отрицательный slope заменяется константным прогнозом prevalence validation, чтобы не менять ориентацию слабого ранжирования. Validation-калибровка и выбор эпохи используют одни данные; независимая оценка калибровки выполняется на внешнем held и test.

Для SVM до калибровки sigmoid(decision_function) является только некалиброванным score, не вероятностью из обученной вероятностной модели. Предсказания до/после калибровки сохраняются раздельно.

- Основные метрики: ROC-AUC и PR-AUC; дополнительно log loss, Brier, F1/precision/recall класса риска, balanced accuracy, ECE10.
- Калибровка: intercept (идеал 0), slope (идеал 1), Brier/log loss/ECE до и после; десять reliability bins и графики. Диагностическая регрессия slope/intercept на test описывает уже полученные прогнозы и не применяется обратно к модели.
- Survival: Harrell C-index только для методов с обучаемым Cox-выходом. Риск каждого фолда стандартизируется по внутренним train-прогнозам перед усреднением. Baselines без survival-головы не получают фиктивный C-index.
- OOF: каждая запись development прогнозируется одним held-фолдом на seed. Для таблицы нескольких seed вероятности усредняются. Внешний test — среднее пяти fold-pipelines и трёх seed; полного refit на всех development-записях нет.
- Mean/std по fold×seed описывают разброс, не являются доверительным интервалом независимых наблюдений. 95% percentile CI ROC-AUC и парной разницы AUC рассчитываются bootstrap по ученикам (1000 повторов).
- Единственный первичный p-value: learner-cluster paired permutation, proposed против no_cox на test основного окна, 1000 перестановок. Остальные CI — исследовательские, без заявления скорректированной множественной значимости.

## Переобучение и недообучение

Для каждой модели сохраняются финальные raw train/validation-метрики, разрывы log loss и AUC, обучение относительно константной prevalence-модели, число эпох/итераций, выбранная эпоха, признаки достижения лимита и предупреждения оптимизатора.

Для нейросетей на каждой эпохе записываются BCE/Cox/total loss, raw validation AUC/log loss, raw train-probe AUC/log loss в eval-режиме и время эпохи. Probe — фиксированная случайная подвыборка до 512 fit-записей, её размер сохраняется. Это ускоряет мониторинг; финальная train-оценка выполняется на всей fit-части. Train и validation на графике измеряются без dropout. Достижение лимита не доказывает недообучение, а train–validation gap сам по себе не доказывает вредное переобучение; данные нужны для научной интерпретации.

## Сохранённые артефакты

`runs/risk_<UTC>/`:

- `run_manifest.json`: задача, настройки, primary contrast, checksum данных/кода, версии, время и статус.
- `environment.json`, `run.log`, `source/`: оборудование, пакеты, лог, снимок использованного кода.
- `day_D/cohort_audit.json`, `cohort_and_folds.csv`: выборка, исключения, составная метка, survival-исходы, роли, номера фолдов.
- `day_D/fold_F/indices.npz`, `preprocessing.joblib`, `features.json`: точные fit/validation/held/test и обученная предобработка.
- Для каждого seed и модели: веса или estimator, калибратор, predictions.npz, training.json, fit_diagnostics.json, calibration_metrics.csv, calibration_bins.csv, learning_curve.csv/png, status.json с checksum артефактов.
- `fold_metrics.csv`, `cv_mean_std.csv`, `summary.csv`, `paired_comparisons.csv`, `calibration_before_after.csv`, `reliability_bins.csv`, `fit_diagnostics.csv`, OOF/test predictions, ROC/PR/calibration-графики.

Новые запуски не перезаписывают исторические результаты. Для продолжения укажите `--resume runs/risk_<UTC>` с теми же параметрами. Завершённые задания повторно не обучаются после проверки checksum; незавершённое задание начинается заново. Для точного resume должны совпасть исходники, данные, версии и параметры. Изменение протокола требует нового каталога.

## Ускорение и пределы

На CUDA используется fused Adam (тот же Adam и FP32); это уменьшает число отдельных запусков GPU-операций. Значение optimizer_fused сохранено в resolved config. Полное время job включает мониторинг, предсказания, калибровку и запись артефактов; fit_with_monitoring_seconds отделяет обучение с validation от остальных расходов. Эти замеры не являются независимым аппаратным benchmark разных архитектур.

Нейросети работают на GPU, FP32, с детерминированными операциями и без TF32; размер batch/архитектура не уменьшаются. Небольшие входные массивы размещаются на GPU один раз на этап; CPU-предобработка общего фолда переиспользуется всеми моделями и seed. Кэшируются неотфильтрованные исходные агрегаты. SVM не выполняет лишнюю внутреннюю калибровочную CV. CPU-потоки ограничены, избегая конкуренции с GPU и избыточного параллелизма. Полное время исследования до реального запуска неизвестно.

Быстрый синтетический тест: `rtk proxy py -3.12 -u run_risk_article.py --smoke --threads 1` (не данные статьи). Проверка окружения: `--check`. Подготовка реальных выборок без обучения: `--prepare-only`.

Методические источники: [PyTorch reproducibility](https://github.com/pytorch/pytorch/blob/main/docs/source/notes/randomness.md), [FastCPH: Efficient Survival Analysis for Neural Networks](https://arxiv.org/abs/2208.09793). Корректность tie-denominator проверяется отдельным тестом против прямого вычисления риск-сетов; название Breslow не означает, что minibatch-объектив равен полному Cox likelihood.
