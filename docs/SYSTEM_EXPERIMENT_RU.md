# Полный эксперимент гибридной системы: 2013, train и validation

## Запуск

Команда работает из любой папки. Создаёт новые каталоги, старые результаты
не заменяет. Test 2014 не читается для оценки и не используется для выбора
моделей. Данные 2013 делятся по студентам, исходная схема 70/30 сохранена.

```powershell
rtk proxy py -3.12 -X utf8 -u "C:\Users\user\Documents\Diser\система\oulad-bilstm-attention\run_system_experiment.py" --windows 7 14 28 56 84 112 140 168 --seeds 42 13 7 23 101 --device auto --threads 6
```

Для первого полного прохода с меньшей длительностью используйте `--seeds 42`.
Это полноценные восемь окон и все методы, но ещё не проверка устойчивости
обучения по seed. Пять seed — основной вариант протокола. Время полного
запуска заранее не гарантируется: прежние 2 ч 25 мин относились к одному
seed прогнозирующей части, без нового эксперимента рекомендаций.

Предварительная проверка окружения — та же команда с `--check`; обучения нет.
Для отдельной проверки рекомендаций по уже завершённым прогнозам:

```powershell
rtk proxy py -3.12 -X utf8 -u "C:\Users\user\Documents\Diser\система\oulad-bilstm-attention\run_system_experiment.py" --risk-run "C:\Users\user\Documents\Diser\система\oulad-bilstm-attention\runs\risk_20261031T162709361455Z" --seeds 42 --threads 6
```

`--max-learners 12` ограничивает только рекомендационные запросы на split и
помечает запуск как пилот, непригодный для итоговых научных выводов. По
умолчанию ограничений нет. Для продолжения прерванного обучения прогнозов
есть `--resume-risk <каталог>`: параметры, версии и контрольные суммы должны
совпадать с исходным запуском. Уже готовый `--risk-run` должен быть completed.
Повторное выполнение рекомендационной части использует новый каталог.

## Что обучается

1. Существующий улучшенный эксперимент: 18 прогнозирующих методов,
   включая LSTM + BiLSTM Attention + LightGBM и второй запрошенный ансамбль.
   8 окон × 18 методов × 5 seed = 720 итоговых оценок. Внутренние trial
   считаются отдельно. Четыре trial, screening 15 эпох, максимум 100 эпох,
   patience 20 и batch 256 сохраняют нынешний протокол.
2. Рекомендации: календарь, популярность fit-студентов текущего курса,
   предпочтения, предпочтения без затухания, гибрид с нейтральным риском,
   гибрид с индивидуальным риском, его вариант без diversity и два
   обучаемых ранжировщика. Вариант без предпочтений изолирует их вклад.
3. Для обучаемых ранжировщиков StandardScaler и LogisticRegression обучаются
   только на fit. C из 0.01/0.1/1/10 выбирается по selection NDCG@10.
   При равенстве остаётся первый, сильнее регуляризованный кандидат.
4. Отдельная Platt-калибровка будущего взаимодействия обучается только на
   calibration. Внешние held-метки не меняют параметры, веса или калибровку.

Исходные индексы fit/selection/calibration/held берутся из нового
прогнозирующего запуска. Проверяется непересечение студентов. Данные
OULAD и три исходных CSV сверяются по SHA-256 с прогнозирующим запуском.
Прогнозы ансамбля для fit восстанавливаются из его сохранённых компонент
и исходных весов; для held дополнительно проверяется совпадение с NPZ.
Старый калибратор ансамбля читается, но не переобучается рекомендациями.

## Метрики завершения обучения

Два отдельных положительных класса:

- неуспех: Fail или Withdrawn;
- успех: Pass или Distinction, вероятность равна 1 − P(неуспеха).

На fit, selection, calibration и held, до и после исходной калибровки:
ROC-AUC, PR-AUC (Average Precision), отдельно trapezoidal PR-AUC,
Precision, Recall, F1, Specificity, Balanced Accuracy, Accuracy,
TP/FP/FN/TN, Brier, Log loss, ECE, MCE, slope/intercept калибровки и
доля положительных примеров. Порог заранее фиксирован: 0.5.
ROC-AUC двух классов совпадает с точностью вычислений; PR-AUC рассчитывается
отдельно. Нельзя сравнивать PR-AUC задач с разной меткой как одну метрику.

Для остальных базовых прогнозирующих моделей сохраняются все прежние
характеристики в исходном каталоге risk_*. Полный эксперимент дополнительно
создаёт двустороннюю таблицу успех/неуспех для основного ансамбля.

## Метрики рекомендаций

Временной срез: история `date < t`, будущая релевантность из положительных
кликов за `[t, t+7)`. Конкретный ресурс определяется через id_site.
Одинаковые кандидаты используются для всех методов. Ресурсы, посещённые
в последние семь дней, исключены одинаково; скрытая невозможность
рекомендовать будущий ресурс отражается в reachable_fraction.

Precision@K, Recall@K, F1@K, NDCG@K, MAP@K, MRR@K, HitRate@K, fill rate
считаются для K = 5/10/20. Дополнительно: доля запросов с будущими позитивами,
условные метрики по таким запросам, Recall по всем будущим ресурсам,
охват доступного held-каталога, Gini экспозиции, novelty относительно
сглаженной популярности fit-студентов, разнообразие типов и Jaccard выдачи
между соседними наблюдаемыми окнами. «Без затухания» использует всю текущую
историю, поэтому это абляция forgetting, а не замороженный прошлый профиль.

PR-AUC/ROC-AUC для будущего взаимодействия считаются по **всем кандидатам**,
без семплирования отрицательных примеров. PR-AUC связан с долей позитивов;
она сохраняется для каждого split. Кандидатные вероятности учитываются
pooled, а ранжирование — macro по запросам. Ненаблюдавшийся клик является
proxy negative, а не доказанной нерелевантностью.

Эвристический score не выдаётся за вероятность: его некалиброванные
Brier/ECE/Log loss имеют значение N/A. Эти показатели вычисляются для
отдельной калиброванной вероятности взаимодействия. Для логистических
ранжировщиков есть оба этапа. Калибровка не переупорядочивает рекомендации.

## Переобучение, неопределённость и ресурсы

Сохраняются train–selection и train–held разрывы ранжирования и прогноза,
матрицы ошибок, reliability bins, коэффициенты, масштабы признаков,
гиперпараметры, n_iter и предупреждения сходимости логистических моделей.
У эвристик нет эпох и train loss; для них не создаются искусственные
learning curves. Кривые нейросетей и диагностики early stopping остаются
в прогнозирующей части. Описательный разрыв сам по себе не является
статистическим доказательством переобучения.

Основной контраст рекомендаций заранее задан: hybrid_risk минус
hybrid_no_risk по NDCG@10 на 56-м дне. CI строится парным bootstrap по
студентам; для метрик @10 также есть отдельные cluster CI. Остальные
окна и сравнения исследовательские; среднее и std по seed хранятся отдельно.
Пять seed не создают пять независимых validation-наборов. Детерминированные
baseline-рекомендации закономерно могут иметь нулевой разброс по seed.

Ускорения: GPU auto для сетей, существующий FP32/deterministic протокол,
одна последовательность обучения на GPU, ограничение CPU/BLAS-потоков,
порционное чтение raw-логов один раз, общий набор кандидатных признаков
на окно для всех методов и seed, повторное использование прогнозов
компонент вместо их повторного обучения. Отрицательные примеры не
семплируются ради ускорения; внешний held не используется для поиска.

Измеряются wall time, CPU time, p50/p95/p99 latency ранжирования, затраты
построения признаков отдельно, RSS/working set каждые 50 мс, OS lifetime
peak, GPU peak и число параметров в существующих training.json, размер
сохранённых файлов. Память GPU рекомендационного CPU-этапа равна нулю.
Выборочный peak RAM может пропускать всплески короче интервала измерения;
OS lifetime peak относится к процессу целиком, а не к одному методу.

## Где смотреть

В конце выводится новый каталог `runs/system_<timestamp>/`:

- system_manifest.json — настройки, статус, пути обеих частей;
- forecast_process_resources.json — ресурсы дочернего процесса прогнозов;
- source/ — точный снимок нового рекомендационного кода;
- recommendations/REPORT_RU.md — отчёт и таблица двух исходов обучения;
- recommendations/figures/ — динамика top-K метрик и качества завершения;
- recommendations/ranking_summary.csv и across_seeds.csv;
- recommendations/course_outcome_metrics.csv;
- recommendations/recommendation_probability_metrics.csv и reliability_bins.csv;
- recommendations/generalization_gaps.csv и forecast_generalization_gaps.csv;
- recommendations/runtime_memory.csv;
- day_N/seed_S/METHOD/ — веса, trial, калибраторы, выдачи, CI и диагностики;
- day_N/candidate_features_and_labels.parquet и queries.csv — воспроизводимые
  кандидаты и временная разметка.

Это ретроспективная learner-disjoint оценка на 2013 году, не подтверждённая
проспективная проверка. Учебная польза рекомендаций не выводится из
совпадения с будущими кликами; для неё нужен отдельный эксперимент.
ASSISTments для этого запуска не требуется и автоматически не добавляется.
